# DataPulse Database Schema

## Overview

DataPulse uses PostgreSQL 16+ with SQLAlchemy 2.x (async mode) and Alembic for schema migrations.

---

## Tables

### `users`

| Column | Type | Constraints |
|---|---|---|
| `id` | UUID | PK |
| `email` | VARCHAR(320) | UNIQUE, NOT NULL, indexed |
| `username` | VARCHAR(50) | UNIQUE, NOT NULL, indexed |
| `hashed_password` | VARCHAR(512) | NOT NULL |
| `is_active` | BOOLEAN | NOT NULL, default `true` |
| `created_at` | TIMESTAMPTZ | NOT NULL, server default `now()` |
| `updated_at` | TIMESTAMPTZ | NOT NULL, server default `now()` |

### `datasets`

| Column | Type | Constraints |
|---|---|---|
| `id` | UUID | PK |
| `owner_id` | UUID | FK → `users.id` ON DELETE CASCADE, indexed |
| `name` | VARCHAR(255) | NOT NULL |
| `description` | TEXT | nullable |
| `original_filename` | VARCHAR(255) | NOT NULL |
| `file_size_bytes` | BIGINT | NOT NULL |
| `storage_path` | VARCHAR(1024) | NOT NULL |
| `status` | VARCHAR(20) | NOT NULL, default `pending`, indexed |
| `error_message` | TEXT | nullable |
| `row_count` | INTEGER | nullable (set after processing) |
| `column_count` | INTEGER | nullable (set after processing) |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `updated_at` | TIMESTAMPTZ | NOT NULL |

**Status values:** `pending` → `processing` → `ready` / `failed`

**Note:** `storage_path` stores the path relative to `UPLOAD_DIR`. The full path is never exposed in API responses.

### `dataset_columns`

| Column | Type | Constraints |
|---|---|---|
| `id` | UUID | PK |
| `dataset_id` | UUID | FK → `datasets.id` ON DELETE CASCADE, indexed |
| `name` | VARCHAR(255) | NOT NULL |
| `inferred_type` | VARCHAR(50) | NOT NULL |
| `position` | INTEGER | NOT NULL |
| `missing_count` | INTEGER | NOT NULL, default `0` |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `updated_at` | TIMESTAMPTZ | NOT NULL |

**Inferred type values:** `integer`, `float`, `datetime`, `string`, `boolean`, `empty`

### `reports`

| Column | Type | Constraints |
|---|---|---|
| `id` | UUID | PK |
| `dataset_id` | UUID | FK → `datasets.id` ON DELETE SET NULL, nullable, indexed |
| `owner_id` | UUID | FK → `users.id` ON DELETE CASCADE, indexed |
| `title` | VARCHAR(255) | NOT NULL |
| `snapshot_json` | TEXT | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `updated_at` | TIMESTAMPTZ | NOT NULL |

**Snapshot:** `snapshot_json` contains an immutable JSON blob (serialized at report creation) with `dataset`, `quality`, and `statistics` sections. This means the report survives dataset deletion and is unaffected by subsequent changes to the dataset.

### `refresh_tokens`

| Column | Type | Constraints |
|---|---|---|
| `id` | UUID | PK |
| `user_id` | UUID | FK → `users.id` ON DELETE CASCADE, indexed |
| `token_hash` | VARCHAR(64) | UNIQUE, NOT NULL, indexed |
| `expires_at` | TIMESTAMPTZ | NOT NULL |
| `revoked` | BOOLEAN | NOT NULL, default `false` |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `updated_at` | TIMESTAMPTZ | NOT NULL |

## Deletion Policy

| Action | Effect |
|---|---|
| Delete user | Cascades to datasets, dataset_columns, reports, refresh_tokens |
| Delete dataset | Cascades to dataset_columns; reports keep their snapshot (dataset_id → NULL) |
| Delete report | Removes only the report row and snapshot; dataset is unaffected |
| Delete uploaded file | Happens after the dataset row is deleted from DB; failure is silently logged |

## Migrations

Alembic is configured for async migrations in `alembic/env.py`.

```bash
# Apply all pending migrations
uv run alembic upgrade head

# Show migration history
uv run alembic history

# Rollback one migration
uv run alembic downgrade -1

# Generate a new migration (after model changes)
uv run alembic revision --autogenerate -m "describe your change"
```

**Warning:** always review autogenerated migrations before applying them. Alembic may not detect every change correctly, especially column renames and complex type changes.

## Entity Relationships

```
users
  │
  ├── datasets (one-to-many, cascade delete)
  │     │
  │     └── dataset_columns (one-to-many, cascade delete)
  │
  ├── reports (one-to-many, cascade delete)
  │     └── dataset (nullable FK, SET NULL on dataset delete)
  │
  └── refresh_tokens (one-to-many, cascade delete)
```
